# Sinsap — ระบบบริหารการเงินส่วนบุคคลและพอร์ตการลงทุน

เว็บแอปสำหรับติดตามหุ้นที่ถือจริง พอร์ต DCA รายรับ รายจ่าย เงินสด เงินสำรอง หนี้สิน และทรัพย์สินสุทธิ ทุกหน้าคำนวณจากฐานข้อมูลชุดเดียวกันด้วยสูตรกลางชุดเดียว ข้อมูลแยกตามผู้ใช้ด้วย Row Level Security ของ PostgreSQL

> เครื่องมือช่วยวิเคราะห์และวางแผนเท่านั้น ไม่ใช่คำแนะนำการลงทุนรายบุคคล ไม่ทำนายราคา และไม่รับประกันผลตอบแทน

## เริ่มใช้งานในเครื่อง

ต้องมี Node.js 20.9 ขึ้นไป (พัฒนาด้วย Node 24)

```bash
npm install
```

```bash
npm run dev
```

เปิด http://localhost:3000 แล้วสมัครบัญชี — **ไม่ต้องตั้งค่าอะไรเลย**: เมื่อไม่มี `DATABASE_URL` ระบบใช้ PostgreSQL แบบฝังในโปรเซส (PGlite) เก็บไฟล์ไว้ที่ `.data/pglite` และ migrate อัตโนมัติ ข้อมูลอยู่ถาวรบนเครื่องนั้น (ปิด/เปิดใหม่ยังอยู่) แต่ **ใช้ข้ามอุปกรณ์ไม่ได้** — สำหรับมือถือ/หลายเครื่องให้ Deploy ตามหัวข้อถัดไป

คำสั่งอื่น:

| คำสั่ง | หน้าที่ |
|---|---|
| `npm test` | Unit + Integration tests (ใช้ PostgreSQL ในหน่วยความจำ) |
| `npm run typecheck` | ตรวจ TypeScript |
| `npm run build` / `npm start` | build และรันแบบ production |
| `npm run db:migrate` | รัน migration กับ `DATABASE_URL` (หรือฐานในเครื่อง) |
| `npm run auth:reset-link -- you@example.com https://your-app` | ผู้ดูแลออกลิงก์รีเซ็ตรหัสผ่าน (กรณียังไม่ได้ตั้งค่าอีเมล) |

ตั้งค่าเพิ่มเติมด้วยการคัดลอก `.env.example` เป็น `.env.local`

## Deploy ใช้งานจริง

มี 2 แบบ เลือกตามขนาดการใช้งาน:

| | Google Sheets + GitHub + Vercel | PostgreSQL (Supabase/Neon) + Vercel |
|---|---|---|
| เหมาะกับ | beta / ผู้ใช้ไม่กี่คน, อยากเห็นข้อมูลใน Google Sheet | ใช้งานจริงระยะยาว, ผู้ใช้หลายคน |
| ตั้งค่า | Service Account + แชร์ Sheet ([คู่มือ](docs/DEPLOY-GOOGLE-SHEETS.md)) | สมัครฐานข้อมูลฟรี + `DATABASE_URL` (ด้านล่าง) |
| ข้อจำกัด | ช้ากว่า, โควตา Google ~60 ครั้ง/นาที, ไม่เหมาะกับการบันทึกพร้อมกันจำนวนมาก | — |

ทั้งสองแบบใช้โค้ดชุดเดียวกัน สูตรเดียวกัน และ RLS เหมือนกัน เปลี่ยนแค่ตัวแปรสภาพแวดล้อม — **คู่มือ Google Sheets + GitHub + Vercel แบบทีละขั้น: [docs/DEPLOY-GOOGLE-SHEETS.md](docs/DEPLOY-GOOGLE-SHEETS.md)** · GitHub Actions ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) ตรวจ typecheck/lint/test/build ทุกครั้งที่ push · อัปโหลดขึ้น GitHub ครั้งแรก: `scripts\push-to-github.cmd <repo-url>`

### แบบ PostgreSQL (Supabase + Vercel)

ขั้นตอนที่ผู้ใช้ต้องทำเอง (ต้องมีบัญชีบริการภายนอก):

1. **สร้างโปรเจกต์ Supabase** (มีแพ็กเกจฟรี) → Project Settings → Database → Connection string
   - คัดลอก **Transaction pooler** (พอร์ต 6543) สำหรับ Vercel
2. **รัน migration** จากเครื่องของคุณ:
   ```bash
   DATABASE_URL="postgresql://postgres.xxxx:รหัสผ่าน@aws-0-xx.pooler.supabase.com:6543/postgres" npm run db:migrate
   ```
   (Windows PowerShell: `$env:DATABASE_URL="..."; npm run db:migrate`) หรือคัดลอกเนื้อหา `db/migrations/0001_init.sql` ไปรันใน Supabase SQL Editor
3. **Deploy บน Vercel**: import repository แล้วตั้ง Environment Variables อย่างน้อย `DATABASE_URL` และ `APP_URL` (+ API key ข้อมูลตลาด + `RESEND_API_KEY`/`EMAIL_FROM` ถ้าต้องการส่งอีเมลรีเซ็ตรหัสผ่าน) — script `vercel-build` จะรัน migration ก่อน build ให้อัตโนมัติ
4. เปิดเว็บจากคอมพิวเตอร์และมือถือ เข้าสู่ระบบด้วยบัญชีเดียวกัน ข้อมูลจะตรงกัน

หมายเหตุ
- แอปนี้ **ไม่ใช้ Supabase Auth และไม่ใช้ anon key** — ใช้ Supabase เป็น PostgreSQL อย่างเดียว ทุกตารางเปิด RLS ไว้แล้ว Data API ของ Supabase จึงเข้าถึงข้อมูลไม่ได้ (ดูเหตุผลใน [การตัดสินใจทางเทคนิค](#สถาปัตยกรรมและการตัดสินใจทางเทคนิค))
- ใช้ PostgreSQL อื่นได้ (Neon, RDS, self-hosted) ขอแค่เป็นเวอร์ชัน 15 ขึ้นไป และ role ที่เชื่อมต่อสร้าง role ได้ (`CREATEROLE`) ตอน migrate
- Preview deployment ที่ชี้ฐานข้อมูลเดียวกับ production จะรัน migration กับฐานจริงด้วย ควรใช้ฐานแยกสำหรับ preview
- ค่าใช้จ่าย: Supabase/Vercel แพ็กเกจฟรีเพียงพอสำหรับใช้ส่วนตัว; ข้อมูลหุ้นไทยต้องใช้ API แบบเสียเงิน (ดูด้านล่าง)

## ข้อมูลตลาดหุ้นและอัตราแลกเปลี่ยน

**API key อยู่ใน Environment Variables ฝั่งเซิร์ฟเวอร์เท่านั้น** เบราว์เซอร์ไม่เคยเห็น key และไม่เคยเรียก API ผู้ให้บริการโดยตรง

ข้อมูลจากหน้าเว็บทางการของผู้ให้บริการ ตรวจสอบเมื่อ 14 ต.ค. 2026 (ราคาและเงื่อนไขเปลี่ยนได้ ควรตรวจซ้ำก่อนสมัคร):

| ผู้ให้บริการ (ตัวแปร) | แพ็กเกจฟรี | หุ้นไทย (SET) | ความสดของข้อมูล | ข้อควรรู้เรื่องสิทธิ์ใช้ข้อมูล |
|---|---|---|---|---|
| **Twelve Data** (`TWELVEDATA_API_KEY`) | 8 req/นาที, 800/วัน | ต้องแพ็กเกจ Pro (เริ่ม ~$99/เดือน), symbol `PTT` + `mic_code=XBKK` | สหรัฐฯ: ระหว่างตลาดเปิด | แพ็กเกจฟรีระบุ "Internal non-display usage" — การแสดงผลในแอปต้องใช้แพ็กเกจ Grow ขึ้นไป (เริ่ม ~$29/เดือน) |
| **EODHD** (`EODHD_API_KEY`) | 20 req/วัน, ข้อมูลย้อนหลัง 1 ปี | แพ็กเกจ "EOD Historical Data: All World" ~$19.99/เดือน, symbol `PTT.BK` | ล่าช้า 15–20 นาที + ราคาปิดรายวัน | ใช้ส่วนตัวไม่เชิงพาณิชย์ได้ ห้ามเผยแพร่/ให้ผู้อื่นเข้าถึง |
| **Alpha Vantage** (`ALPHAVANTAGE_API_KEY`) | 25 req/วัน | ไม่พบหลักฐานว่ารองรับ | ฟรี: ราคาปิดสิ้นวัน, ย้อนหลัง 100 วัน | Real-time/Delayed ต้องแพ็กเกจเสียเงิน (เริ่ม $49.99/เดือน) |
| **Frankfurter** (FX, ไม่ต้องใช้ key) | ไม่จำกัด (มี rate limit กันการใช้ผิด) | THB รองรับ | อัตราอ้างอิงรายวันจากธนาคารกลาง | สำรอง: open.er-api.com (ต้องให้เครดิต) |

คำแนะนำ: ใช้ส่วนตัวเฉพาะหุ้นสหรัฐฯ → Twelve Data ฟรีใช้งานได้ทันที (แต่ตรวจเงื่อนไขการแสดงผล); ต้องการหุ้นไทยด้วย → EODHD แพ็กเกจ All World ตั้ง `MARKET_PROVIDER_TH=eodhd` (และ `MARKET_PROVIDER_US=eodhd` ถ้าต้องการใช้เจ้าเดียว) · ถ้าเปิดให้คนอื่นใช้ ต้องมีสัญญา display/redistribution กับผู้ให้บริการ

พฤติกรรมของระบบ
- หน้าเว็บ **ไม่รอ API**: แสดงราคาจากฐานข้อมูลทันที แล้วเบราว์เซอร์ขอให้เซิร์ฟเวอร์อัปเดตเฉพาะราคาที่ถึงเวลา (ตลาดเปิด: ทุก 15 นาที, ตลาดปิด: ครั้งเดียวหลังราคาปิด) ทุก 10 นาที หรือกดปุ่ม "อัปเดตราคา"
- คุมโควตาด้วยตาราง `api_usage` (ต่อนาที/ต่อ 24 ชม.) — ครบโควตาแล้วหยุดเรียกและแจ้งว่าข้ามตัวไหน หุ้นที่ถืออยู่ได้รับการอัปเดตก่อน
- ทุกราคาแสดงประเภท **Real-time / Delayed / End-of-day / Cached (เก่าเกินเกณฑ์) / บันทึกเอง** พร้อมเวลาของราคาและเวลาที่ดึง
- API ล้มเหลว → เก็บราคาเดิมโดย **ไม่** ประทับเวลาใหม่ แสดงการแจ้งเตือนพร้อมข้อความผิดพลาด
- ไม่มี API key → ไม่มีราคาสร้างขึ้นเอง หุ้นแสดง "ไม่มีข้อมูลราคา" และมูลค่าพอร์ตแสดงสถานะไม่ครบ ผู้ใช้บันทึกราคาเองได้ (ติดป้าย "บันทึกเอง")
- เวลาทำการตลาดคิดตามเวลาปกติ (US 09:30–16:00 ET, SET 10:00–12:30 และ 14:30–16:30) **ไม่รวมวันหยุดตลาด**
- กราฟใช้ราคาปิดรายวัน ยังไม่มีข้อมูลระหว่างวัน (ปุ่ม 1D ถูกปิดพร้อมคำอธิบาย)

## หลักการคำนวณ

สูตรทั้งหมดอยู่ใน `src/lib/calc/` (pure functions มี unit test) และหน้าเว็บทุกหน้าอ่านผลจาก `buildSnapshot()` ตัวเดียว

| ตัวเลข | นิยาม |
|---|---|
| ต้นทุน | **Weighted Average Cost** ต่อพอร์ตต่อหลักทรัพย์: ซื้อ → ต้นทุน += จำนวน×ราคา + ค่าธรรมเนียม; ขาย → ต้นทุนส่วนที่ขาย = ต้นทุนเฉลี่ย × จำนวนที่ขาย |
| กำไรที่รับรู้แล้ว | (ยอดขาย − ค่าธรรมเนียมขาย) − ต้นทุนเฉลี่ยของหุ้นที่ขาย |
| มูลค่าพอร์ต | จำนวนหุ้นคงเหลือ × ราคาล่าสุด × อัตราแลกเปลี่ยนล่าสุด (เฉพาะที่มีราคา; ไม่ครบ = แสดงสถานะไม่ครบ) |
| กำไร/ขาดทุนที่ยังไม่รับรู้ | มูลค่าตลาด − ต้นทุนของหุ้นที่ยังถือ; % = ÷ ต้นทุน × 100 |
| สกุลเงิน | ทุกธุรกรรมเก็บอัตรา (บาทต่อ 1 หน่วย) ณ วันทำรายการ → ต้นทุนเป็นบาทตามจริง; กำไรเป็นบาท = ผลราคา + ผลค่าเงิน, กำไรสกุลต้นทาง = ผลราคาอย่างเดียว |
| เงินปันผล | แยกจากกำไร/ขาดทุนราคา บันทึกยอดก่อนภาษี + ภาษีหัก ณ ที่จ่าย |
| ผลตอบแทนรวม | ยังไม่รับรู้ + รับรู้แล้ว + ปันผลสุทธิ − ค่าธรรมเนียมอื่น (ค่าคอมซื้อขายอยู่ในต้นทุน/ยอดขายแล้ว) |
| แตกหุ้น | จำนวน × อัตรา, ต้นทุนรวมเท่าเดิม |
| เงินสดคงเหลือ | ยอดยกมา + รายรับที่ได้รับจริง − รายจ่ายที่จ่ายจริง − ชำระหนี้ ± โอน ± ซื้อขายหุ้นที่ผูกบัญชี |
| การกันนับซ้ำ | โอนเงินเข้าโบรกเกอร์ = ย้ายเงิน (ไม่ใช่รายจ่าย); ซื้อหุ้นจากบัญชีโบรกเกอร์ = เงินสดลด หุ้นเพิ่ม (ไม่ใช่รายจ่าย) |
| หนี้คงเหลือ | ยอดเริ่ม + ดอกเบี้ย + ค่าธรรมเนียม + ก่อหนี้เพิ่ม − ชำระ; ดอกเบี้ยใช้ตัวเลขจริงถ้ากรอก มิฉะนั้นประมาณแบบรายวัน (ยอด × อัตรา/365 × วัน) และติดป้าย "ประมาณ" |
| เงินสำรองเป้าหมาย | ค่าใช้จ่ายจำเป็นต่อเดือน (ตั้งเอง หรือเฉลี่ย 3 เดือนล่าสุดจากรายจ่ายที่ติด "จำเป็น") × จำนวนเดือน; เงินลงทุนไม่นับเป็นเงินสำรอง |
| เงินพร้อมใช้เดือนนี้ | เงินสด/ธนาคารที่ไม่ได้กันไว้ − บิลค้างจ่ายถึงสิ้นเดือน − หนี้ขั้นต่ำที่ยังค้างเดือนนี้ |
| ทรัพย์สินสุทธิ | เงินสดทุกบัญชี + ทรัพย์สินอื่น + มูลค่าพอร์ต − หนี้สิน |
| Growth Simulator | r = (1+R)^(1/12) − 1, FV = P(1+r)^n + C×((1+r)^n − 1)/r, ลงทุนปลายเดือน |

ตัวเลขใช้ double precision และปัดเศษทุกขั้น (จำนวนหุ้น 8 ตำแหน่ง ต้นทุน 6 ตำแหน่ง เงินสด 4 ตำแหน่ง) เพื่อไม่ให้ความคลาดเคลื่อนสะสม; ขายหมดได้ศูนย์พอดีเสมอ

## สถาปัตยกรรมและการตัดสินใจทางเทคนิค

```
Browser ──(Server Actions / RSC)──> Next.js 16 (App Router, Node runtime)
                                     ├─ src/lib/auth      ระบบสมาชิก (scrypt, session token แบบ hash)
                                     ├─ src/lib/services  กฎธุรกิจของการบันทึกข้อมูล (transaction ต่อคำขอ)
                                     ├─ src/lib/calc      สูตรกลาง (pure) → Snapshot เดียวต่อคำขอ
                                     ├─ src/lib/market    ผู้ให้บริการข้อมูลตลาด + cache + rate limit
                                     └─ src/lib/db        PostgreSQL (pg) หรือ PGlite + RLS ต่อผู้ใช้
```

การตัดสินใจสำคัญ (บันทึกไว้เพื่อการดูแลต่อ):

1. **PostgreSQL เป็นแหล่งข้อมูลเดียว ไม่ใช้ localStorage** — localStorage ใช้เฉพาะธีมของอุปกรณ์
2. **ระบบสมาชิกของแอปเอง แทน Supabase Auth** — สเปกอนุญาต "Supabase Auth หรือระบบที่ปลอดภัยเทียบเท่า" เลือกแบบนี้เพราะ (ก) ทดสอบได้ครบแบบ end-to-end ในเครื่องโดยไม่ต้องมีบัญชีบริการภายนอก (ข) ไม่ผูกกับผู้ให้บริการรายเดียว — ใช้ PostgreSQL ใดก็ได้ (ค) โค้ดยืนยันตัวตนเป็นจุดเดียว ตรวจสอบง่าย มาตรการ: scrypt ตามค่าที่ OWASP แนะนำ, token สุ่ม 256 บิตเก็บแค่ SHA-256, cookie HttpOnly + SameSite=Lax + Secure (production), rate limit, ข้อความไม่เปิดเผยว่ามีอีเมลนี้หรือไม่, reset token ใช้ครั้งเดียวและออกจากระบบทุกอุปกรณ์ ข้อแลก: ไม่มี OAuth/2FA/ยืนยันอีเมลในตัว (เพิ่มได้ภายหลัง)
3. **RLS บังคับโดยฐานข้อมูล** — ทุกคำขอรันเป็น role `app_user` ที่ไม่มี BYPASSRLS ภายใต้ `app.user_id` ของผู้ใช้ จึงไม่ต้องพึ่ง `WHERE user_id = ...` ในโค้ดอย่างเดียว (มี integration test ยืนยันว่าผู้ใช้หนึ่งอ่าน/แก้/ลบ/อ้างอิงข้อมูลของอีกคนไม่ได้) ดู [docs/DATABASE.md](docs/DATABASE.md)
4. **PGlite สำหรับในเครื่องและการทดสอบ** — PostgreSQL ตัวจริง (คอมไพล์เป็น WASM) จึงรัน migration, RLS, constraint ชุดเดียวกับ production; ทำให้ `npm run dev` ใช้ได้ทันทีและ integration test รันได้ทุกเครื่อง
5. **Snapshot เดียวต่อคำขอ** — `buildSnapshot(raw, market, today)` เป็นฟังก์ชัน pure ที่ทุกหน้าใช้ ตัวเลขจึงไม่ขัดกันข้ามหน้า และทดสอบได้โดยไม่ต้องมีเว็บ
6. **ไม่เก็บยอดคงเหลือ** — ยอดเงิน จำนวนหุ้น ต้นทุน ยอดหนี้ คำนวณจากรายการเสมอ การแก้ไข/ลบรายการย้อนหลังจึงถูกต้องอัตโนมัติ; การแก้ที่ทำให้ประวัติ "ขายเกินจำนวนที่ถือ" ถูกปฏิเสธทั้ง transaction
7. **Next.js 16 Cache Components** — ทุกหน้าเป็น static shell + เนื้อหาผู้ใช้ stream หลัง `<Suspense>` (เป็น Loading state ในตัว) ไม่มีการ cache ข้อมูลผู้ใช้ (`use cache` ไม่ถูกใช้เลย) หลังบันทึกข้อมูลเรียก `revalidatePath('/', 'layout')` ให้ทุกหน้าอ่านข้อมูลใหม่
8. **ข้อมูลตลาดเป็นตารางกลาง** — ราคาหุ้นไม่ใช่ข้อมูลส่วนบุคคล ผู้ใช้หลายคนที่ถือหุ้นเดียวกันใช้ cache ร่วมกัน ประหยัดโควตา

## ความปลอดภัย

- ทุก Server Action: ตรวจ session → ตรวจ input ด้วย zod (ฝั่ง client ตรวจด้วยเพื่อความสะดวก) → รันใน transaction ต่อผู้ใช้ → ข้อความผิดพลาดที่ไม่เปิดเผยรายละเอียดภายใน
- CSRF: Server Actions ตรวจ Origin กับ Host (Next.js) + cookie SameSite=Lax
- กันบันทึกซ้ำ: ปุ่มถูกปิดระหว่างบันทึก + idempotency key ที่ฐานข้อมูลบังคับ unique
- ยืนยันก่อนลบ/แก้รายการสำคัญ, Audit Log แบบ append-only
- Security headers (X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy)
- CSV export ป้องกัน formula injection
- ไม่มี secret ในโค้ดฝั่ง client; `.env*` ถูก ignore (ยกเว้น `.env.example`)

## สำรองและกู้คืนข้อมูล

| วิธี | ใช้เมื่อ |
|---|---|
| Settings → "ดาวน์โหลดข้อมูลทั้งหมด (JSON)" | สำรองข้อมูลของตัวเองเป็นไฟล์ (ทุกตาราง + Audit Log ล่าสุด) |

| Supabase: Daily backups / PITR | สำรองทั้งฐานข้อมูลโดยผู้ให้บริการ |
| `pg_dump "$DATABASE_URL" -Fc -f sinsap.dump` และ `pg_restore -d "$DATABASE_URL" --clean sinsap.dump` | สำรอง/กู้คืนทั้งฐานด้วยตัวเอง |
| ฐานในเครื่อง (PGlite) | หยุดเซิร์ฟเวอร์แล้วคัดลอกโฟลเดอร์ `.data/pglite` ทั้งโฟลเดอร์ |

## ข้อจำกัดที่ทราบ

- รายรับ รายจ่าย และหนี้ บันทึกเป็นสกุลเงินหลัก (บาท) เท่านั้น; บัญชีเงินสดและหุ้นเป็นสกุลอื่นได้
- ไม่มีการเชื่อมบัญชีโบรกเกอร์โดยตรง (บันทึกเองหรือนำเข้า CSV)
- เวลาทำการตลาดไม่รวมวันหยุด, ไม่มีข้อมูลราคาระหว่างวัน (intraday)
- ไม่มีข้อมูลองค์ประกอบของ ETF — การตรวจถือซ้ำซ้อนใช้ "กลุ่มสินทรัพย์" ที่ผู้ใช้กำหนดและหมวดธุรกิจ
- Corporate actions รองรับแตกหุ้น/รวมหุ้นและรายการปรับปรุง; spin-off/merger ต้องบันทึกเป็นรายการปรับปรุงเอง
- ระบบส่งอีเมลผ่าน Resend ยังไม่ได้ทดสอบกับ key จริง (ไม่มีบัญชีในการพัฒนา)
- การเรียก API ของผู้ให้บริการข้อมูลตลาดทดสอบด้วยรูปแบบข้อมูลจริงที่บันทึกไว้ (mock) — ยังไม่ได้ทดสอบกับ API key จริง
